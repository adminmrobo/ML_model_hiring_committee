招聘启事 — 用数据做判断

混凝土工厂里有一位老员工，名叫手册先生。他按照作业标准里写的 if 规则判定配合比：“水胶比小于 0.5 且养护 28天以上，即为 35 MPa 合格。”就靠这一行，他撑了好几年。

可是，掺了矿渣粉和粉煤灰的新配合比、只养护了 7天的试件、“连等级也要评定”的要求，一下子全来了。要修改规则，需要判断所依据的知识，而这种知识恰恰没有。委员会得出结论：与其让人来写知识，不如招一位能从数据中自己生成知识的员工。这就是机器学习，而这一集就是它的招聘启事。

01
What is a judgment

什么是判断 — 看输入，选其一

判断是“思考”的一种。判断的依据（知识）由谁来写，区分了基于规则和机器学习

判断机器 · 放入一个配合比试试
人工智能 · 机器学习 · 深度学习

基于规则也是人工智能

20 世纪 80 年代广泛使用的专家系统，是把专家知识转换成数百行 if 规则的程序。因为它代替了人的判断，所以被称为人工智能。手册先生也属于这一脉。机器学习的不同之处只有一点：它用数据生成判断的依据（规则）。深度学习则是机器学习中，用层层堆叠的神经网络连特征也一起学习的分支。

“判断是思考的一种形式”是个不错的起点，但这个比喻也有失灵的地方。人的判断还包含目的、责任和对情境的理解。本系列的模型只从带答案的数据中学习输入 → 决定的对应关系，并不知道自己为什么做这件事。

Rules · IF, flowchart, logic

用规则做判断 — IF、流程图、逻辑运算

手册先生的作业标准，用一行 Excel IF函数就能写出来

Excel IF函数 · 选一个要测试的配合比，公式就会计算 

      

      
嵌套 IF — 想连等级也评定的话

      
=IF(AND(水胶比<0.4, 龄期>=28), "高强度",
   IF(AND(水胶比<0.6, 龄期>=7), "普通", "低强度"))

      
每多一个问题，IF 就多一层。阈值 0.4·0.6·7天是人凭感觉选的值（第03章会测量这个嵌套 IF 的成绩）。

    

    

      逻辑运算 · 打开、关闭 A 和 B 试试
      

      

      

      
NOR 是“只有两者都不成立时才为真”。只把多个 NOR 门连起来，就能构成 AND·OR·NOT。所以 NOR 被称为“万能门”。判断规则归根结底也是这样的真假组合。

    

  

  

    流程图 · 配合比经过的路径会亮成蓝色
    
    
上面 IF函数中选的配合比会沿这条路径走。流程图中的一个菱形就是一个 IF，连接菱形的“是 → 是”就是 AND。

Where rules break

    
规则失灵之处 — 新材料和短龄期

    
写规则需要知识。知识不够，规则就会变多，变多的规则会相互冲突

规则失灵的三种情形

    
    
      
  • 没有知识。新手手册只看水和水泥。它不知道矿渣粉和粉煤灰随着时间推移也会像水泥一样硬化，所以在掺了这些材料的配合比上错得很厉害。专家用“胶凝材料”这一概念把三者合在一起。这一条知识就改变了准确率。
    • 
      
  • 规则变多、相互冲突。加上高效减水剂条款（第三条）后，有的配合比判对了，有的却判错了。如果还要评定等级（低·普通·高），就会出现嵌套 IF，每个阈值都得靠感觉。第02章的嵌套 IF 在训练数据上只有 …。
    • 
      
  • 一个数分不清所有情况。即使水胶比相同、龄期相同，骨料和减水剂不同，强度也不同。用两个阈值画出的矩形跟不上这种形状。
    • 
    

  

  

    
技术面试官 · 果蝇研究员一直挪阈值的话，训练得分可以一直往上涨。所以试卷只能在最后打开一次。打开以后再改，那就是看着试卷答题了。

04

    
Rules from data

    
用数据生成规则 — 先是数值，再到形状

    
规则的形状由人定、数值由数据定 → 连形状也由数据定

  

  

    两种工作方式
    
  

  

    

      第 1 步 · 规则形状不变，只让阈值数值由数据决定
      
保持专家手册的形状（“水胶比 < ○ 且龄期 ≥ ○”）不变，把两个数值交给机器。机器在训练的 772 组上把可能的阈值组合逐一试遍，选出答对最多的组合。

      

      

      
专家手动设定的阈值（0.50，28天）：训练 75.6% · 试卷 76.7%

    

    

      第 2 步 · 连形状也由数据决定（预习 5-4 逻辑回归）
      
这一次连规则的形状也不给定。逻辑回归用各特征乘以权重再相加得到的得分来判断，它会从训练数据中自己找出权重。我们比较两种情况：给它 8 个原始特征，以及给它用专家知识做成的 2 个特征（水胶比、log 龄期）。

      

      

      
按下按钮，就会用训练的 772 组学习，再用试卷的 258 组评分。

    

  

  

    
那么知识就没用了吗

    
不是。第 2 步中，得到专家所做两个特征的模型比得到八个原始特征的模型更好。机器学习不是抛弃知识，而是在知识用尽之处用数据接着写下去。“给它什么特征”在整个系列中始终是人的工作。

05

    
Regression vs classification

    
答案的形态 — 是回归，还是分类？

    
判断结果是连续的数就是回归，是可数的标签就是分类

  

  
想一想基于规则的结果就容易理解了。如果手册的答案是“42.6 MPa”这样有大小的数，就是回归；如果是“合格 / 不合格”或“低·普通·高”这样从几个标签中选一个，就是分类。标签可以是两个（二分类），也可以是多个（多分类）。拿不准时，问一问“答案的大小和差值有意义吗？”即使写成数字，只要它只起标签的作用，就是分类。

同样的数据，三个问题

    
本系列的监督学习本部用同一份 1,030 组混凝土配合比提出全部三个问题：“强度是多少 MPa？”（回归，5-1~5-3）、“是否超过 35 MPa？”（二分类，5-4）、“属于低·普通·高哪一档？”（多分类）。数据相同，变的只是问题。

06

    
Supervised vs unsupervised

    
有没有答案 — 监督学习本部与无监督学习本部

    
记有判断结果（答案）的是监督学习；连判断标准都没有、要寻找结构的是无监督学习

  

  

    同样的配合比，显示答案时与遮住答案时
    

    

    

    

  

  

    
从基于规则的角度看
如果有手册先生写下的“合格·不合格”记录，就可以招一位模仿这些记录的员工（监督）。如果根本没有记录，只是好奇“配合比能分成几类？”，员工就会自己制定标准来分组（无监督）。

    
在本系列中
监督学习本部（5-1~5-9）用这份混凝土数据面试，无监督学习本部（5-10~5-15）用 1,797 张手写数字（scikit-learn load_digits）面试。数字数据即使遮住答案，分组也很明显，适合展示“不用答案进行分组”。

      • 数据与计算。实操考题是 UCI Machine Learning Repository 的 Concrete Compressive Strength 数据（Yeh, 1998，1,030 组，CC BY 4.0）。试卷（258 组）按 test_size=0.25、stratify=强度三档、random_state=42 划分，页面与 Colab 代码使用相同的行。强度等级阈值（25·45 MPa）、合格标准（35 MPa）以及手册先生的阈值（水胶比 0.5、龄期 28天）都是为教学设定的值，不能代替 KS 等实际的设计、质量标准。手册先生的规则、阈值搜索和逻辑回归预习，都由本页在浏览器中直接计算。逻辑回归用梯度下降求解，小数点后可能与 scikit-learn 略有不同。第05章卡片中工厂代码、出货量的例子仅用于说明。
      • 申请表·第1页。各集第00章的九格申请表是为本系列新绘制的。逻辑回归一集沿用了一张广为流传的九格总结信息图的结构（二分类 → 线性得分 → Sigmoid函数 → 概率 → 边界 → 阈值 → 损失 → 学习 → 多分类），没有搬用原图和标志。
      • 图片。登场人物的图片沿用自《人工智能算法家族组织图》。面试室场景、工牌和图表由本页用代码直接绘制。
      • “招聘委员会”设定。这是把模型比作应聘者、把训练和评估比作面试的比喻，并不代表真实的招聘流程或某家公司。不录用只表示“不适合这份工作”，并不是模型的优劣之分。
      • 登场人物。博士、助理、果蝇研究员、算盘宝、手册先生和应聘者均不代表真实人物。台词中关于钱和预算的说法，是比喻计算成本的口头禅。
      • 数据。监督学习本部的实操考题是 UCI Machine Learning Repository 的 Concrete Compressive Strength 数据（Yeh, 1998，1,030 组，CC BY 4.0）。各集统一的试卷划分为 test_size=0.25、stratify=强度三档、random_state=42（训练 772 · 试卷 258）。强度等级（25 · 45 MPa）和合格标准（35 MPa）是本系列为教学设定的阈值，不能代替任何设计标准。
      • 语言。本系列用韩语写成。译本（English · 中文 · 日本語 · Oʻzbekcha · Русский）在韩语版内容定稿后以相同文件名追加。Colab 代码中的注释和运行结果保留韩语原文。
