GBM——接过前一棵树的错题本

5-7 随机森林是分别询问一百棵树再求平均。今天的应聘者则一棵接一棵地立树。第一棵树大致答对之后，第二棵树只学第一棵树还差多少（残差）。第三棵树学加到第二棵之后仍剩下的误差。这是一场把错题本交给下一个人的接力。

GBM（Gradient Boosting Machine，梯度提升）把几百棵深度约为3的浅树串接起来。每棵树的答案只按学习率（通常为0.1）的程度相信并累加。强度（回归）和35MPa合格（分类）都用同样的方法。即使是分类，内部的树也是预测数字的回归树。XGBoost·LightGBM·CatBoost 是把这一原理实现得更快、更稳健的同一家族。

2. 残差 Residual = What's Still Wrong

实际值与到目前为止的预测之差。它成为下一棵树的目标。

ri = yi − F(xi)
等于把平方误差的梯度反过来（第6格）

3. 浅树 Weak Learner · Shallow Tree

一棵树是只会问几个问题的弱员工。叶节点上写着该格子残差的平均值。

本次面试的树：深度3 = 最多提问3次，最多8个叶节点
只用一棵树 R² 为0.12。单独来看很弱
→ 01 自我介绍

4. 累加更新 Additive Model

从一个平均值开始。把树的答案按学习率缩小后依次相加。

FM(x) = F0 + η Σm=1..M hm(x)
→ 04 试用期

5. 学习率 Learning Rate · Shrinkage

不完全相信一棵树的答案，只采纳一点点（η）。越小需要的树越多。

Fm = Fm−1 + η · hm
学习率 × 树的数量成对挑选
→ 04 试用期

6. 名字的含义：梯度 Gradient in Function Space

残差是损失函数梯度的反方向。所以叫“梯度”提升。

−∂L/∂F = y − F = 残差
树用梯度下降直接修正预测值本身
→ 04 试用期

7. 分类也用回归树 Log-odds · Classification

即使是35MPa合格问题，树累加的也是数字（对数几率）。Sigmoid函数把它换成概率。

p = σ(F) ,   残差 = y − p
F₀ = log(合格比例 ÷ 不合格比例)
→ 05 绩效考核

8. 树的数量与早停 Early Stopping

训练误差会无止境地减小，验证误差却在某一刻停住。就在那时停止。

验证集从训练数据中划出，不是试卷
scikit-learn：n_iter_no_change、validation_fraction

一次一棵，只学错的部分

最初的预测只是一个数：训练强度的平均值。对所有配合比都回答同一个值，所以 R² 为0。第一棵树学习预测“偏离平均值多少”（残差）。把它的答案按学习率缩小后加上，预测就好一点，残差也小一点。第二棵树学习变小后的残差。如此重复几百次。每棵树都是只有两三个提问的弱学习器，但依次填补各不相同的失误，就会变强。这种把弱者串起来变强的方法叫作提升法。

F₀ = 平均 → r = y − F → h = 树(r) → F ← F + η·h →（重复）

和随机森林有什么不同

两者都是使用几百棵树的集成学习。5-7 随机森林把深树并排培育。每棵树重新抽取数据，使它们各不相同，再把答案求平均来减小摇摆（方差）。GBM 把浅树排成一列培育。下一棵树学习前面的树剩下的误差，把答案相加来减小偏斜（偏差）。所以随机森林可以一次把树都种好，而 GBM 必须等前一棵树完成才能开始下一棵。

随机森林：平均(深树们)  ·  GBM：平均 + η·Σ(浅树)

02
Practical test · Data

实操考题 — 同一张配合比表，两个问题

每一行是一组配合比（样本），配合用量和龄期是特征(X)，抗压强度(MPa)和35MPa合格是目标(y)

任务 A · 回归

预测抗压强度 (MPa)

用 R²（1为完美，0为总是只答平均值）和 MAE（平均错了多少 MPa）打分。录用线是手册先生的现场经验公式（Abrams公式 + 龄期修正）在试卷上得到的 R² 0.735。

任务 B · 分类（+ 三档）

35 MPa 是否合格

录用线是 5-0 手册先生用作业标准书中的一行规则（“水胶比低于0.5且28天以上”）在试卷上答对的 76.7%，基线（总猜不合格）为49.6%。此外还看低强度·普通·高强度三档（基线45.0%）。

GBM 读考题的方式 · 对树来说没有单位陷阱

5-1 KNN 要测距离，所以把 kg 和天直接相加时，近邻就变得莫名其妙。树不测距离。它只看一个特征内的大小顺序，比如“水泥是否不超过350kg？”。标准化不改变顺序（减去再除以之后，大的仍然大），所以树挑选的划分不变，预测也不变。用右边的按钮亲自确认一下。

按下按钮，就用训练集772组训练两次 GBM：一次用 kg·天的原单位，一次用标准化后的值。

树读得懂的和读不懂的

树靠划分阈值工作。因为它问的是“龄期是否不超过14天？”这样的问题，所以即使龄期是1·3·7·28天这样零散的值，即使水胶比和龄期相互交织改变强度（像“只有28天以上时水才重要”这样的交互），它也能接连提问跟上去。但树的答案是台阶。在训练数据中没有的范围（水胶比0.2、龄期1,000天），它直接回答最末一级台阶的值。和 5-1 KNN 一样，它不能外推。

更换数据说明 — 想换成自己工厂的数据时

  • 只要是表格形式（CSV 等），每行一组配合比（或一个批次），有一列要预测的值即可。只改 Colab 代码（A章）第1格的数据读取、FEATURES、PASS_MPA。
  • 不做标准化也可以。不过如果和其他应聘者放进同一个流水线，做了也无害。
  • 有缺失值时，HistGradientBoosting 可以直接接收。GradientBoosting 因版本而异，请查阅文档或预先填补。
  • 文字形式的特征（工厂、原材料等级）用独热编码，或者用 HistGradientBoosting 的 categorical_features、CatBoost 的类别特征处理。
  • 行数超过几万时，换成 HistGradientBoosting（或 LightGBM·XGBoost）（第06章）。

    ④ 版本备忘——同一个 GBM，名称也一直在变
    
    
    scikit-learn GBM 的损失名称改过。回归的 loss="ls" 改成了 "squared_error"（1.0 中预告，1.2 中删除），分类的 loss="deviance" 改成了 "log_loss"（1.1 中预告，1.3 中删除）。现在用旧名称会报 InvalidParameterError。criterion="mse" 也走了同样的路。HistGradientBoosting 以前必须先导入 from sklearn.experimental import enable_hist_gradient_boosting，从 1.0 起就不需要了。
    
    
    XGBoost·LightGBM·CatBoost 提供与 scikit-learn 相似的 fit/predict，但参数名称和默认值不同。学习率有时叫 learning_rate，有时叫 eta；树的大小有时不用深度（max_depth）而用叶节点数（num_leaves）来定；设置早停的位置也随版本换来换去。AI 给出的参数要用自己所装版本的官方文档核实。正因如此，本页A章的代码只用 scikit-learn。

    为什么不能相信训练 R²
    
      
    树累加得越多，训练残差只会减少。树总是学习“剩下的误差”，一直做下去，连每个试件的偶然（配合比相同、强度却不同的试件）都会背下来。所以训练 R² 一路向1攀升，而在没见过的配合比上的成绩会在某一刻停住或下降。η = 1.0 的曲线就是这个样子：完全相信一棵树的答案，升得快，也折得早。
    
    
    
    
    
      
    早停——验证集发出停止信号
    
      
    验证 R² 不再上升时就停止。这就是早停。在 scikit-learn 中用 n_iter_no_change=10, validation_fraction=0.1 开启。它先留出训练数据的10%，连续10棵没有改善就停止（A章第7格：在257棵时停止）。这次面试是人看着图定的。在验证曲线变平的区间内，无论选多少棵成绩都差不多，所以取整数 300棵（η = 0.1，深度3）作为上岗条件。试卷仍然密封着。
    
    
    
  
    
  
    
    
    预算官算盘宝账我算好了。一棵树最多7个阈值、8个叶节点值。300棵就要背约4,500个数字。比 KNN 的6,176个少。可训练得排队一棵一棵来，没法分摊着快点干完。预测一组提问900次就完事，这部分倒便宜。

    GBAPP-09 → EMP-0009GBM（梯度提升）监督学习本部 › 两用组 · 集成学习
    
      
    一句话评价：把剩下的误差一直填到底的员工。在表格数据上最常拿第一的家族。不过上岗条件多，排成一列工作所以训练难以分摊，干得太久还会连偶然都背下来。
    
    
    
    
    
      
    
        
    优点
    
        
      
          
    • 在表格数据上成绩高。本次面试的回归 R² 0.949 是目前所有应聘者中最高的（第06章中期结算）。
      • 
          
    • 不需要标准化。它靠划分阈值工作，单位不同也没关系（第02章）。
      • 
          
    • 能自己找到交互和弯曲的关系。龄期与水胶比交织的效应，它靠接连提问就能跟上。
      • 
          
    • 回归·分类·排序同一框架。只要换损失函数即可。分类的内部也是回归树。
      • 
        
    
      
    
      
    
        
    缺点
    
        
      
          
    • 上岗条件多。学习率·树的数量·深度·子采样要一起挑选。用默认值也做得不错，但最好的成绩来自调参。
      • 
          
    • 依次学习。前一棵树完成后才能培育下一棵，训练难以分摊。所以才出现了快速实现（Hist·LightGBM·XGBoost）。
      • 
          
    • 放久了就会死记硬背。训练准确率99.9%，试卷93.4%。需要早停和较小的学习率。
      • 
          
    • 难以解释。300棵树之和说不出“是因为这一条”。特征重要性只是“用得多频繁、多重”，不是原因。
      • 
        
    
      
    
    
    
  
    
  
    
    上岗条件 · 常调的超参数（scikit-learn GradientBoostingRegressor / GradientBoostingClassifier）
    
    
      
    参数默认值含义与用法
    
      
        
    n_estimators100要累加的树的数量（分类中类别在三个以上时，每阶段的树数与类别数相同）。本次面试为300。即使用默认值100，回归 R² 0.927、分类91.9%也能录用。
    
        
    learning_rate0.1相信一棵树答案的程度 η。调小并增加树，通常成绩会变好，但训练时间变长。与树的数量成对挑选（第04章）。
    
        
    max_depth3一棵树的提问数。默认用浅树（2~5）。长到底（None）的话，第一棵树就背下了训练数据，后面的树没有残差可学（A章第8格：试卷 R² 0.890）。
    
        
    subsample1.0设成小于1（如0.8），每棵树只随机使用训练数据的一部分（随机梯度提升）。能减轻过拟合并加快速度。
    
        
    min_samples_leaf1叶节点中最少的配合比数。调大后，迎合单个偶然试件的叶节点就会消失。
    
        
    n_iter_no_change, validation_fractionNone, 0.1早停。从训练数据中留出验证集，在规定的棵数内没有改善就停止。停止时的树数量保存在 n_estimators_。
    
        
    loss"squared_error" / "log_loss"要最小化什么。回归中异常值多时用 "huber" 或 "absolute_error"，区间预测用 "quantile"。旧名称 "ls"、"deviance" 现在会报错（第03章）。
    
          
    
    
  
    
  
    
    同一原理，不同实现 · 对残差（梯度）累加树的家族
    
    
      
    实现有何不同本次面试的试卷
    
      
    
    
    
    XGBoost·LightGBM·CatBoost 不在本构建环境中，所以没有直接运行。Colab 中一般都已安装，可以用B章提示词③在同一份试卷上比较。名称不同的参数和默认值，请查阅官方文档确认。
    
  
    
  
    
    中期结算 · 截至监督学习本部两用组——五位应聘者（5-5 ~ 5-9）在同一份试卷258组上
    
    
    
    
  
    
  
    
    
    预算官算盘宝看结算表，随机森林和 GBM 的分类得分一模一样嘛。那我就把硬币押在训练能分摊的那个，或者像 HistGradientBoosting 那样快的。得分一样，便宜的员工赢。
    
  
    
  
    
    适合的工作 · 不适合的工作
    
    
      
    适合的工作特征在几十到几百个的表格数据的回归·分类（质量预测、需求预测、不良判定、信用评估），需要最高成绩并且有时间调整上岗条件的业务，竞赛和实务中的强基线
    
      
    不适合的工作图像·声音·长文本等原始数据庞大的数据（适合深度学习），需要预测训练范围之外的工作（设计更高强度的配合比），必须以条款说明判断依据的业务（手册先生或浅决策树更好），数据极少的工作
    
      
    补充在表格数据上“先从 GBM 系列试起”是个好习惯。但要把那个得分与手册先生（人的知识）和简单的应聘者（线性模型）放在一起看。得分差异小时，也可以选更容易解释的那个。

      设定与注意事项
      关于本页数据、图片和设定的说明
      
  
      • 数据与计算。实操考题是 UCI 混凝土抗压强度数据1,030组，试卷是按 test_size=0.25、stratify=强度三档、random_state=42 划分出的258组。回归录用线是手册先生的现场经验公式（把Abrams公式推广到水胶比并乘以 ACI 209R 龄期修正的公式，无学习）在试卷上得到的 R²，分类录用线是 5-0 手册先生的作业标准书得到的准确率。35MPa 合格标准和25·45MPa的分档阈值是为教学设定的值。第01·02·04·05章、面试结果以及第06章中期结算中 5-9 一行，由本页在浏览器中直接培育树来计算（与 scikit-learn GradientBoosting 规则相同：起始值、friedman_mse 划分、叶节点值、学习率。得分相同的划分有多个时，挑选顺序可能不同）。浏览器中的数据副本把强度四舍五入到小数点后两位，所以回归 R² 与 Colab（A章）在小数点后第三位略有不同（300棵：浏览器0.950，Colab 0.949）。第04章的验证集是把训练配合比按行号顺序排列、每五行取一行得到的，与A章第6格相同。预先计算的值只有第06章的 HistGradientBoosting 得分、中期结算中 5-1 ~ 5-8 各行，以及第05章的随机森林特征重要性，全部用 Python（scikit-learn 1.9.1，random_state=0）计算，A章第11·12格会得出相同的值。XGBoost·LightGBM·CatBoost 在本构建中没有运行。第03章的“AI 给出的代码”是汇集常见失误故意制作的示例，并非某个 AI 服务的真实回答。
