# 모델 채용 위원회 — 제작 재현 매뉴얼

이 문서는 「모델 채용 위원회 — 머신러닝 열다섯 명의 입사 면접」 최종본(16편 × 6개 언어)을 **처음부터 같은 결과로 다시 만드는 절차**다. 사람이 읽어도, AI에게 그대로 넘겨도 따라 할 수 있게 썼다. 단계(Phase)마다 끝에 **체크리스트(게이트)**가 있다. 게이트를 모두 통과해야 다음 단계로 간다.

- 설계 결정(컨셉·등장인물·말투·편 구성·연출)은 `docs/모델채용위원회_컨셉_설정.md`가 원본이다. 이 문서는 **만드는 순서와 검사 방법**을 다룬다.
- 번역 절차와 번역 규칙의 원본은 `i18n/README.md`다.
- 이 문서의 명령은 모두 묶음 맨 위 폴더(`model_hiring_committee/`)에서 실행한다.

### P3. 5-0 채용 공고 (허브)

1. 5-0은 면접이 아니라 공고다: 룰 베이스(IF 함수·순서도·NOR) → 규칙의 한계 → 데이터로 만드는 규칙 → 회귀·분류 → 지도·비지도 → 면접 규칙 → **전체 지도(#m8)**.
2. 매뉴얼 씨의 면접 결과(보류)가 첫 합격선 76.7%를 만든다.

### P9. 공용 조각 검토 (번역 품질의 핵심)

```bash
python3 qa/shared_review.py collect ja                    # qa/review/ja_ctx.json, ja_keys_a/_b.json
# 검토자 2명(a, b 절반씩)에게: "i18n/_brief_shared.md를 읽고 LANG = ja, HALF = a로 따르라."
python3 qa/shared_review.py render ja - bd520550adf1      # 한 조각이 편마다 어떻게 읽히는지 직접 보기

```

고치는 순서: ① 모든 편에 맞는 중립 번역(common) → ② 그 편에서만 다르게(`i18n/<언어>/_overrides.json`) → ③ 이웃 조각 손질(ep).

| 러시아어 표가 화면보다 넓음 | 긴 단어 | 번역판 표 칸에 `overflow-wrap:anywhere; hyphens:auto` |

| 화면 점검이 한글을 못 잡음 | 검사에서 `<pre>` 전체를 제외 | 검사 제외는 Colab 코드 영역(`pre.code`, `#codebox`, `.runshot`)만 |

## 6. 고칠 때의 절차 (유지보수)

**한국어 본문을 고쳤을 때**
1. `ep/` 또는 `src/` 수정 → `python3 build.py <편>` → `python3 qa/check_pages.py ko`
2. `python3 i18n/extract.py` — 바뀐 조각만 `tr`이 비고, 옛 번역은 `i18n/<언어>/_stale.json`에 남는다(참고용)
3. 다섯 언어의 빈 `tr`을 채운다(옛 번역을 참고) → `tools.py check` → `build.py` → `qa/check_pages.py`
4. `make_site.py` → 바뀐 파일만 업로드

**새 언어를 더할 때**: `build.py`의 `LANGS`·`FONTS`, `src/core.js`의 `LANGS`, `make_readme.py`의 언어 사전에 추가 → § P7 ~ P11을 그 언어로 반복.

**새 편을 더할 때**: § P4 → `EPISODES`, 5-15 결산표 `FINAL`, `qa/check_numbers.py`의 `EXPECT`, README 편 표 갱신 → `extract.py`부터 번역 반복.
