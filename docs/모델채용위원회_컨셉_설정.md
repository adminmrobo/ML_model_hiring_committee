# 모델 채용 위원회 — 컨셉 설정

이 문서는 머신러닝 모델 시리즈(5-0 ~ 5-15, 목차 포함 17편)의 **컨셉, 등장인물, 대사 규칙, 편 구성, 디자인, 다국어 방식**을 정한다. 각 편을 만들 때 이 문서를 먼저 따른다.

| 항목 | 결정 |
|---|---|
| 시리즈 이름 | **모델 채용 위원회 — 머신러닝 열다섯 명의 입사 면접** |
| 영문 이름 | The Model Hiring Committee — Fifteen Machine-Learning Candidates |
| 한 줄 컨셉 | 콘크리트 공장의 품질 판단을 매뉴얼(if 규칙) 대신 맡길 직원을 뽑는다. 지원자는 머신러닝 모델 열다섯 명이다 |
| 편 수 | 목차 1 + 0편(채용 공고) + 면접 15편 = HTML 17개 × 6개 언어 |
| 등장인물 | 패밀리 시리즈의 네 명을 다시 쓴다. 역할만 바꾼다 |
| 원칙 | 주제는 모델이다. 컨셉은 제목·이름표·대사·장식에만 쓰고, 개념 설명 문장은 쉬운 말 그대로 둔다 |

## 1. 이야기의 뼈대

회사는 콘크리트 공장이다. 오래 일한 직원 **매뉴얼 씨**는 현장 경험칙을 적은 작업 표준서대로만 판단한다. "물-결합재비가 0.5 미만이고 28일 이상 굳혔으면 35MPa 합격." 이 한 줄은 대부분 맞는다. 그런데 슬래그·플라이 애시·고성능 감수제를 섞은 새 배합, 7일만 굳힌 시편, 등급까지 매겨 달라는 요청이 들어오자 규칙이 늘고, 늘어난 규칙끼리 부딪히고, 규칙을 쓸 **지식**이 없는 곳에서 매뉴얼 씨는 멈춘다.

그래서 위원회가 열린다. **판단의 근거가 되는 지식을 데이터에서 스스로 만드는 직원**을 뽑는다. 0편은 채용 공고, 1~15편은 지원자 한 명씩의 면접이다.

- **합격선**: 0편에서 매뉴얼 씨가 봉인된 시험지(테스트 데이터)에서 낸 점수가 첫 합격선이다. 지원자는 이 점수와 "늘 가장 흔한 답만 하는 기준선"을 넘어야 한다.
- **판정은 숫자가 한다**: 면접 결과는 페이지가 브라우저에서 직접 계산한다. 위원장은 숫자를 읽고 판정할 뿐이다.
- **불합격도 있다**: 데이터 모양이 지원자와 맞지 않으면 보류·불합격이 나온다. "모든 일에 맞는 모델은 없다"가 시리즈 전체의 결론이다.

- 지원자와 매뉴얼 씨는 그림 대신 **사원증 카드**(기호 + 이름)로 그린다. 새 그림이 없어도 된다.
- 초파리와 주판봇은 위원회 안의 두 관점이다. **일반화·설명**(초파리) 대 **비용·단순함**(주판봇). 둘 다 판정권은 없다.
- 본문 섹션 하나에 말풍선은 최대 1개. 캐릭터는 히어로, 판정, 마무리에 주로 나온다.
- 무기·폭력·비하 표현은 쓰지 않는다. 불합격 지원자도 "이 일과 맞지 않는다"고만 말한다.

## 6. 디자인

- **인사 서류철**: 밝은 화면은 서류 종이(미색)와 남색 잉크, 어두운 화면은 야근하는 사무실. 강조색은 도장 빨강(합격 도장)과 파랑(모델·연결).
- **지원서 1장**은 어느 모드에서나 흰 종이에 파랑으로 그린다. 첨부 인포그래픽의 9칸 구성을 따르되 그림은 모두 새로 그린다(원본 로고·이미지는 옮기지 않는다). 파랑 = 모델·연결, 검정 = 데이터.
- 글꼴: 본문 IBM Plex Sans KR, 서류 칸·숫자 IBM Plex Mono, 도장 Black Han Sans.

## 7. 다국어

- 한국어가 원본이다. 저장소 맨 위에 한국어, `en/ zh/ ja/ uz/ ru/`에 같은 파일 이름으로 둔다.
- 위쪽 메뉴의 언어 선택 상자로 바꾼다. 기본(한국어) 주소로 처음 오면 브라우저 언어판으로 이동하고(지원하지 않는 언어면 한국어), 고른 언어는 기억해 기본 주소에 다시 오면 그 언어로 간다. 언어 폴더 주소(`en/` 등)를 직접 열면 그 언어를 유지한다. `?lang=en`으로 직접 지정할 수 있다.
- **번역 방식**: 페이지를 언어마다 복사하지 않는다. 한글이 든 조각(HTML 문단·말풍선·속성, 스크립트 문자열)을 `i18n/extract.py`로 뽑아 카탈로그(`i18n/source/`, 공용 + 편별 17개, 약 10,150조각 · 57.8만 자)로 만들고, 번역(`i18n/<언어>/*.json`의 `tr`)을 빌드 때 끼운다. 키는 한국어 원문의 해시라서 원문을 고치면 그 조각만 다시 번역하면 된다. 자세한 절차와 번역 규칙은 `i18n/README.md`.
- 용어집은 `i18n/glossary/<언어>.json`(시리즈 고정어 + 콘크리트 20 + 모델 용어, 295개). 고정 영문: The Model Hiring Committee · the Chair (Doctor) · the HR Assistant · the Fruit Fly · AbaBot · Mr. Manual · Hired / On hold · the hiring bar.
- **진행 상황 (2026-10-23)**: 6개 언어(한국어 원본 + 영어·중국어(간체)·일본어·우즈베크어(라틴)·러시아어) 16편 모두 완료. 언어마다 10,154/10,155조각(남은 하나는 언어 상자의 "한국어"), 검사 오류 0, 80개 번역 페이지 전부 휴대폰 폭·실행 오류·남은 한글 점검 통과. 면접 판정(Hired·录用·採用·Ishga olindi·Принят)과 콘크리트 판정(Pass·合格·Oʻtdi·Годен)은 소스의 `/*i18n:verdict*/` 꼬리표로 나눈다. 언어별 결정은 `i18n/<언어>/_conventions.md`, 편별 예외는 `_overrides.json`.
- 그 편과 공용 조각의 90% 이상이 번역되면 그 언어가 선택 상자에 열린다. 그 전에는 "준비 중".
- Colab 코드(A장)의 주석과 실행 결과는 한국어 원문 그대로 둔다. AI 프롬프트(B장)는 번역하며 "주석을 그 언어로" 쓰도록 바꿨다.
- 배포: `python3 make_site.py` → `site/`(언어 폴더 + `.nojekyll`)를 GitHub Pages 저장소 루트에 올린다.

## 8. 데이터

| 본부 | 실기 과제지 | 쓰는 질문 |
|---|---|---|
| 지도 본부 (5-0 ~ 5-9) | **콘크리트 압축 강도** — UCI Concrete Compressive Strength (Yeh, 1998), 1,030건, CC BY 4.0 | 회귀: 강도(MPa) · 이진 분류: 35MPa 이상인가(합격) · 다중 분류: 저강도(<25)·보통(25~45)·고강도(≥45) |
| 비지도 본부 (5-10 ~ 5-15) | 손글씨 숫자 (scikit-learn `load_digits`, 1,797장, 8×8) | 군집, 차원 축소 (정답은 채점에만) |

- 특징 8개: 시멘트, 고로 슬래그, 플라이 애시, 물, 고성능 감수제, 굵은 골재, 잔골재(kg/m³), 재령(일). 파생 특징: 결합재 = 시멘트+슬래그+플라이 애시, **물-결합재비** = 물 ÷ 결합재.
- 시험지 나누기 규정(전 편 공통): `train_test_split(test_size=0.25, stratify=강도 3등급, random_state=42)` → 훈련 772, 시험 258.
- **매뉴얼 씨(룰 베이스)**: 현장 경험칙 "물-결합재비 0.5 미만이고 28일 이상 굳혔으면 35MPa 합격" → 시험지 정확도 76.7%(198/258) = 첫 합격선.
- Colab에서는 `ucimlrepo`의 `fetch_ucirepo(id=165)`로 받는다. 빌드는 같은 내용의 로컬 사본(`data/concrete.csv`)으로 실행 결과를 만든다.
- 등급 문턱(25·45MPa)과 합격 기준(35MPa)은 수업용으로 정한 값이며 KS 등 설계 기준을 대신하지 않는다.
- 검토했다가 뺀 데이터: Fish Market(쉬움, 제조 톤과 다름), 타이타닉(실제 참사라 톤 문제), AI4I 2020(공개된 생성 규칙으로 만든 합성 데이터라 규칙을 아는 룰 베이스가 모든 모델을 이기고, 트리 계열에만 유리함).

## 9. 공통 용어 사전

콘크리트 전문용어 20개(재령, 28일 강도, 압축 강도, MPa, 결합재, 물-결합재비, 물-시멘트비, 시멘트, 고로 슬래그, 플라이 애시, 혼화재, 고성능 감수제, 굵은 골재, 잔골재, 배합, 시편, 양생, 수화, 레미콘, 에이브럼스 식)는 `src/core.js`의 `DOMAIN_GL` 한 곳에 둔다. 모든 편의 C장 용어 정리 맨 위에 "콘크리트" 묶음으로 붙고, 본문에서는 그 편에서 처음 나올 때 한 번만 점선 밑줄(말풍선 설명)이 달린다. 편의 GL에 같은 용어가 있어도 공통 정의가 우선한다. 번역 때 언어별 용어집의 기준표로 쓴다.

## 11. 비지도 본부 (5-10 ~ 5-15)

- **업무 이야기**: 콘크리트 공장의 현장 일지와 시험 성적서에는 손으로 쓴 숫자가 수천 장 쌓여 있다. 정답 이름표를 하나하나 붙일 사람이 없다. 비지도 본부 지원자는 **정답 없이** 비슷한 글씨끼리 묶거나(군집팀), 64칸짜리 글씨를 2차원 지도로 펼친다(차원축소팀). 사람은 묶음마다 대표 몇 장에만 이름을 붙이면 된다.
- **데이터**: scikit-learn `load_digits` 1,797장(8×8 픽셀, 밝기 0~16). 정답(0~9)은 학습에 쓰지 않고 "채점 봉투"에 봉인해 채점에만 쓴다. 정답을 쓰지 않으므로 시험지를 따로 떼지 않고 1,797장 전체로 학습한다.
- **매뉴얼 씨**: 사람이 정한 세 규칙(가운데가 비었나 · 잉크가 많나 · 위가 무거운가)으로 8묶음 → ARI **0.108** = 군집팀 합격선. 같은 두 숫자(잉크 양, 위쪽 비율)로 그린 2D 지도에서 5-NN 정확도 **18.1%** = 차원축소팀 합격선.
- **채점**: 군집팀은 ARI(숨긴 정답과 겹침, 무작위 ≈ 0)와 실루엣 점수(정답 없이 재는 점수)를 함께 본다. 차원축소팀은 2D 지도에서 5-NN 정확도(5겹 교차 검증)와 설명된 분산을 본다. 판정: 합격선과 무작위 기준선을 모두 넘으면 합격.
