PCA — 64マスを最も広がる2つの軸へ回して立て直す

工場の現場日誌と試験成績書に、手書きの数字が1,797枚積まれている。1枚は8×8 = 64マスの明るさである。人の目には絵だが、コンピュータにとっては数64個、つまり64次元空間の点1つである。64次元は描くことも、ざっと眺めることもできない。

今日の応募者PCA（Principal Component Analysis、主成分分析）は影遊びをする。点の雲に光を当てて壁（軸）を回し、影が最も長く広がる方向を1番目の軸に選ぶ。その軸と直角な方向の中で、また最も広がる向きが2番目の軸である。この2つの軸に映った影が、そのまま64マスの文字の2次元マップになる。正解（どの数字か）は一度も見ない。

Principal Component AnalysisPCA · 主成分分析 · 応募書類・1枚目
PC

1. 文字1枚 = 点1つ 64 Pixels = 64 Dimensions

8×8の明るさ64個を1行に伸ばすと、文字1枚は64次元空間の点1つである。

→ 02 実技課題

2. 影遊び Projection

点の雲に光を当て、壁（軸）に影を落とす。影の位置が新しい座標である。

z = (x − 平均) · v
v = 長さ1の軸の方向
→ 01 自己紹介

3. 最も広がる方向 1st Principal Component

影が最も長く広がる向きへ壁を回す。その方向が第1主成分である。

v₁ = argmax|v|=1 Var(z)
→ 01 自己紹介

4. 2番目の軸は直角に Orthogonal Axes

最初の軸と直角な方向の中で、また最も広がる向き。軸同士は情報を重ねて持たない。

→ 01 自己紹介

5. 共分散と固有ベクトル Covariance · Eigenvectors

64マス同士が一緒に明るくなる度合いを64×64の表にし、その表の固有ベクトルを求める。

→ 04 試用期間

6. 寄与率 Explained Variance Ratio

k本の軸が全体の広がりの何%を担うか。数字の文字では、2軸で28.5%、21軸なら90%。

λk ÷ (λ1 + ⋯ + λ64)
→ 04 試用期間

7. 成分の図 Components as Images

成分も64個の値なので、8×8に折りたためば図になる。青は明るく、赤は暗くするマス。

→ 04 成分の図

8. 再構成と捨てた情報 Reconstruction

いくつかの得点から文字を復元する。成分が少ないとぼやける。その差が捨てた情報である。

x̂ = 平均 + Σk zk vk
→ 05 人事考課

9. 用途と限界 Map · Preprocessing · Linear Only

マップ、圧縮、他の応募者の前処理。ただし軸は常にまっすぐな直線である。

→ 06 人事カード
青： モデル / つながり黒： データ

この1枚を読む順番

1番のマスが「何を受け取るか」（64マスの文字）、2〜4番が「どう軸を選ぶか」（影、最も広がる方向、直角な2番目の軸）、5〜6番が「どう計算し、どれだけ担ったか」（共分散の固有ベクトル、寄与率）、7〜8番が「軸とは何で、何を捨てたか」（成分の図、再構成）、9番が「どこで使い、どこで行き詰まるか」である。この面接は01章（2・3・4番） → 02章（1番） → 04章（5・6・7番） → 05章（8番） → 06章（9番）と進む。

01
Self-introduction · Concept

自己紹介 — 影が最も長く伸びる方へ

平均を中心へ → 軸を回して影の広がりを測る → 最も広がる方向が軸1 → それと直角な方向が軸2

応募者・PCA64次元は描けませんので、まず2つのマスだけお見せします。下の図は、1,797枚の2つのマス（1行5列、2行5列）の明るさです。棒を回して、影が最も広く広がる所を探してみてください。私が64マスでしている仕事がまさにそれです。
触ってみよう · 手書き文字1,797枚の2つのマスの明るさ、軸を回して影の広がり（分散）を測る

なぜ「最も広がる」方向なのか

影が1点に集まると、文字同士を区別できない。影が広く広がるほど、文字ごとに違う位置を得る。広がりを測る数が分散である。PCAは分散が最も大きい方向を1番目の軸（主成分1）に選ぶ。こう選ぶと、その軸1本で再構成するときに失う情報（二乗誤差）が最も小さい。「最も広がる方向」と「最も失うものが少ない方向」は同じことである。

軸1 = 影の分散が最大の方向 = 再構成誤差が最小の方向

2番目の軸は直角に、正解なしで

2番目の軸は、最初の軸と直角な方向の中で、また最も広がる方向である。直角なので2つの軸の得点は互いに相関が0で、同じ情報を2回持たない。64マスなら、こうして軸を64本まで立てられる。その中で前の数本だけを残すのが次元削減である。この過程全体で「この文字がどの数字か」は一度も使わない。だから教師なし学習である。

軸2 ⊥ 軸1 · 軸3 ⊥ 軸1, 2 · ⋯ · 軸64

課題 · 2次元マップを描く

64マスの文字を2Dマップに広げる

応募者は正解を見ずに、文字ごとに座標を2つ決める。マップが良いかどうかは、描き終えた後に封筒を開けて測る。マップで最も近い5枚の正解で当ててみる5-NN正解率（5分割交差検証）である。同じ数字同士が集まったマップほど高い。

採用ラインとベースライン

マニュアルさんのマップ 18.1%

マニュアルさんは、人が決めた2つの数、インク量（64マスの明るさの合計）と上側の割合（上4行のインク ÷ 全体）でマップを描いた。そのマップの5-NN正解率18.1%が採用ラインである。ベースラインは、最も多い数字だけを答える（10.2%）とランダムなマップ（約10%）である。

PCAが課題用紙を読む方法

PCAにとって、文字1枚は64マスの明るさのリストにすぎない。隣り合ったマスであることも、絵であることも知らない。その代わり、1,797枚を一緒に見て「どのマスが一緒に明るくなったり暗くなったりするか」（共分散）を数える。縁のマス（いちばん左・右の列）はほぼ常に0なので分散が0に近く、軸を決めるのにほとんど関わらない。64マスはすべて同じ単位（明るさ0〜16）なので、標準化しないのが基本である。標準化すると、ほぼ空の縁のマスの小さな揺れが他のマスと同じ大きさになり、軸を揺さぶる（05章で見直す：マップ 60.3% → 51.4%）。

データ差し替えの案内 — 自分の工場のデータに替えるには

  • 1行にサンプル1つ、列が数値の表であればよい。Colabコード（A章）の1番セルのXだけを変える。正解がなくてもよい（あれば採点にだけ使う）。
  • 列の単位が互いに違えば（温度 ℃、圧力 MPa、時間 日）、まず標準化する。この課題のように単位が同じときだけ、そのままにする。大きな単位の列が軸を独占してしまうからである。
  • 欠損値があるとPCAは受け付けない。先に埋める。
  • 文字列の列（工場、原料の等級）はPCAに向かない。ワンホットに変えることはできるが、解釈が難しくなる。
  • 写真のように列が数千個あればsvd_solver="randomized"、行が多すぎてメモリに入らなければIncrementalPCAを使う（06章）。

    ④ バージョンメモ — 同じPCAでも計算の道筋は変わってきた
    
    
    古いコードに見られるfrom sklearn.decomposition import RandomizedPCAはずっと前になくなった。今はPCA(svd_solver="randomized")と書く。scikit-learn 1.5からは、行が列よりはるかに多いとき、svd_solver="auto"が共分散行列を直接解く"covariance_eigh"を選ぶことがある。このページがブラウザで行う計算（04章）と同じ道筋である。どの道筋で解いても軸の方向は同じだが、符号（+/−）はバージョンや解き方によって反転することがある。マップが左右反転して出てきても間違いではない。
    
    
    n_componentsには整数（軸の数）だけでなく、0と1の間の小数（例：0.9 = 90%を担う分だけ）や"mle"も入れられる。explained_variance_は軸ごとの分散（単位のある値）、explained_variance_ratio_が割合（合計1）である。AIが2つを取り違えることがよくある。引数と属性の名前は自分がインストールしたバージョンの公式ドキュメントで確認する。

    Probation · Finding the axes
    
    
    試用期間 — 軸を1本ずつ探す
    
    
    平均を引く → 64×64の共分散の表 → 最も広がる方向を繰り返し掛けて探す → 見つけた取り分を引いて次の軸 → 何本の軸を残すかを決める
    
  
    
  
    PCAの試用期間は短い。繰り返し直しながら学ぶ他の応募者と違い、共分散の表を1つ解けば軸が決まる。その「解く過程」を目で見るために、下では最も簡単な方法であるべき乗法で軸を探す。どの方向からでも始めて、共分散の表を掛けて長さを1に揃えることを繰り返すと、向きがひとりでに最も広がる方へ回っていく。

    「エルボー」と「90%」 — 何本の軸を残すか
    
      
    正解なしで決めるルールがいくつかある。① 累積の割合が80・90・95%に届く所（このデータでは13・21・29軸）。② 棒が急に低くなり、肘（エルボー）のように折れ曲がる所。手書き文字では折れ目がはっきりしない。③ 用途で決める。人が見るマップなら2（または3）軸、他の応募者に渡す前処理なら90〜95%を担う20〜30軸である。この面接の課題はマップなので2軸である。
    
    
    
    
    
      
    固有値 = その軸の分散
    
      
    共分散の表Cに軸の方向vを掛けると、同じ方向にλ倍伸びたベクトルが出てくる（C v = λ v）。このvが固有ベクトル、λが固有値である。λはその軸に映した影の分散と等しい。64個の固有値をすべて足すと64マスの分散の合計（全体の広がり）になるので、λ ÷ 合計 が「寄与率」である。共分散の表は対称なので、固有ベクトル同士は常に直角である。01章の「直角な2番目の軸」はここから出てくる。
    
    
    
  
    
  
    
    
    予算担当 Money-Robo帳簿を整理したぞ。2Dマップ1つで覚える数は、平均64個 + 軸2本 × 64 = 192個。学習は64×64の表を1回作って解くだけだから、このブラウザで-ms。新しい文字が来ても掛け算128回でマップに載る。繰り返しの学習がないから残業代もなしだ！

    ひとこと評：速くて正直なまっすぐな定規。同じデータならいつも同じ軸を出し、軸の意味を図で見せ、新しいデータも掛け算数回でマップに載せる。その代わり、まっすぐな軸しか使えないので、曲がって重なった群れを2軸に広げることはできない。
    
    
    
    
    
      
    
        
    強み
    
        
      
          
    • 速く、結果がいつも同じ。表を1つ解くだけなので、繰り返しの学習も、初期値の運もない。
      • 
          
    • 軸の意味が見える。成分が64マスの図なので、「何を見て分けたか」を見せてくれる（04章）。
      • 
          
    • 新しいデータもすぐマップに。平均を引いて軸と掛ければ終わり（transform）。5-15 t-SNEにはできない。
      • 
          
    • 捨てた取り分を測れる。寄与率と再構成誤差で「どれだけ捨てたか」を数値で言える。
      • 
          
    • 他の応募者の前処理に向く。ノイズを減らして次元を下げ、GMM・K-Meansを安定させる。
      • 
        
    
      
    
      
    
        
    弱み
    
        
      
          
    • まっすぐな軸しか使わない。群れが曲がっていたりねじれていたりすると、2軸マップで重なる（5・8・1が真ん中で重なる、マップ60.3%）。
      • 
          
    • 「広がり = 重要」と信じている。最も広がる方向が数字を分ける方向だという保証はない。正解を見ないのだから。
      • 
          
    • 単位に敏感。単位の違う列には標準化が必要で、同じ単位ならしない方がよい（02章）。
      • 
          
    • 成分は混ざっている。1つの成分が64マスに+/−で少しずつかかっているので、「この成分はまさにこれ」と言い切りにくい。
      • 
        
    
      
    
    
    
  
    
  
    
    勤務条件 · よく調整するハイパーパラメータ（scikit-learn PCA）
    
    
      
    引数既定値意味と使い方
    
      
        
    n_componentsNone（すべて）残す軸の数。整数ならその個数、0〜1の小数ならその分の分散を担う最小の個数（0.9 → このデータでは21）、"mle"なら統計的に推定。マップは2、前処理は90〜95%。
    
        
    whitenFalseTrueなら軸ごとに得点をその軸の標準偏差で割り、すべての軸の分散を1に揃える。後ろに距離ベースのモデルを付けるとき、小さな軸まで同じように大きくするので、ノイズも大きくなることがある。
    
        
    svd_solver"auto"解き方。"full"（厳密）、"covariance_eigh"（行 ≫ 列のとき速い、1.5から）、"randomized"（列が数千個のときの速い近似）、"arpack"。得られる軸は同じで、符号だけが違うことがある。
    
        
    random_stateNone"randomized"・"arpack"でのみ使われる。毎回同じ結果にするには固定する。
    
        
    (前処理) StandardScaler—PCAの引数ではないが、最も重要な決定である。列の単位が違えば入れ、同じなら外す。この課題では外した（入れるとマップは51.4%）。
    
          
    
    
  
    
  
    
    次元削減チームのマップ比較 · 同じ1,797枚、同じ採点（2Dマップ 5-NN 5分割）
    
    
    
    
  
    
  
    
    他の応募者の前処理 · PCAが減らした空間の上で働くクラスタリングチーム
    
    
      
    使う所何を渡すか結果（ARI、隠した正解との重なり）
    
      
    
    
    
    ARIはクラスタリングチームの採点スコアである（1 完璧、ランダム ≈ 0、クラスタリングチームの採用ライン 0.108）。5-13 GMMは64マスのままだと、釣鐘1つごとに64×64の共分散を10回当てはめる必要があり、不安定である。PCAが30軸（分散の95.9%）に減らして渡すと、クラスタリングチーム1位のスコアが出る。
    
  
    
  
    
    同じ一族 · 軸の選び方を変えた親戚たち
    
    
      
    名前（scikit-learn）何が違うか
    
      
        
    IncrementalPCAデータを少しずつ分けて読みながら軸を更新する。メモリに入りきらない大きなデータ用。
    
        
    TruncatedSVD平均を引かずに分解する。大部分が0の疎行列（単語の頻度表など）に使う。文書ではLSAと呼ぶ。
    
        
    KernelPCAカーネルで空間を曲げてからPCAを行う（5-8 SVMのカーネルトリックと同じ考え）。まっすぐな軸の限界を一部超えるが、カーネルとγを選ぶ必要があり、n×nの表を解くので重い。
    
        
    SparsePCA · NMF成分のマスの大部分を0に（スパース）、またはすべて+に（NMF）して、「この成分はこの画」のように読みやすくする。その代わり、担う分散は少なくなる。
    
        
    FactorAnalysis · ICAマスごとに違うノイズを別に置いたり（因子分析）、軸同士を無相関ではなく互いに「独立」になるように選んだりする（ICA、混ざった信号の分離）。
    
          
    
    
  
    
  
    
    
    実務面接官のショウジョウバエ記録しておくぞ。マップ担当としては採用ラインを3倍超えたが、5と8が真ん中で重なるのはまっすぐな軸の限界だ。マップだけ見て「この群れはこの数字」って名前を広げたら、半分近く間違える。その代わり、30軸で渡す前処理担当としては最高だ。
    
  
    
  
    
    向いている仕事 · 向いていない仕事
    
    
      
    向いている仕事データを最初に受け取ったときに全体の形をざっと見る最初のマップ、列の多い測定データ（数十個のセンサー、スペクトル、画像）の圧縮とノイズ削減、クラスタリング・分類の応募者の前段の前処理、互いに絡み合った（相関の大きい）列をいくつかの独立した得点にまとめること、工程の異常監視（再構成誤差が急に大きくなる供試体を探す）
    
      
    向いていない仕事曲がったりねじれたりした群れを2Dにきれいに広げる必要がある仕事（5-15 t-SNE・UMAP）、列の単位がばらばらなのに標準化できない仕事、軸ごとに「これは何か」というはっきりした名前が必要な報告書（スパースPCA・NMFの方が良い）、文字列の列が多い表
    
      
    補足正解を見ない応募者なので、「最も広がる方向」が「数字を分ける方向」といつも同じとは限らない。正解があるなら、LDA（線形判別分析）のように正解を使う軸の選び方もある。それは教師あり本部の仕事である。

      • 正解なしでも軸を選べる。影が最も広く広がる方向、つまり共分散の表の固有ベクトルである
      • 軸も64マスなので図として見られ、いくつかの得点で文字を再構成し、捨てた取り分を測れる
      • まっすぐな軸2本ではすべてを広げられない。マップは採用ラインを超えたが重なりが残り、30軸で渡すと他の応募者（GMM）が1位になる

      設定と注意事項
      このページのデータ、図、コンセプトについての案内
      
  
      • データと計算。実技課題は、scikit-learnに入っている手書き数字load_digitsの1,797枚（UCI Optical Recognition of Handwritten Digitsの一部、CC BY 4.0、8×8ピクセル、明るさ0〜16）である。正解（0〜9）は軸を選ぶのに使わず採点にだけ使い、正解を使わないので試験用紙を切り離さず1,797枚全体で学習する。採用ラインは、マニュアルさんが人の決めた2つの数（インク量、上側の割合）で描いた2Dマップの5-NN正解率（5分割交差検証、Python 18.1%）である。このブラウザで同じマップを測り直すと18.4%になるが、インク量が同じ文字が多く、近傍5枚を選ぶときの同点の処理順がscikit-learnと違うためである。01・04・05章と面接結果のPCA（平均を引く → 共分散行列 → ヤコビ回転による固有値分解）、2Dマップとk成分の空間の5-NN採点（scikit-learnのStratifiedKFoldと同じ5分割）、再構成、べき乗法の再生、05章の業務スコアのK-Means（k-means++による開始、10回開始してイナーシャが最小のもの）は、すべてこのページがブラウザで直接計算する。PCAと5-NNの数値はColab（A章）と同じである。K-Meansは初期値の乱数がscikit-learnと違うので、代表10枚で名前を付けるスコアは初期値ごとに40〜50%の間で揺れ、既定の初期値（シード3）はColabの結果（49.4%）に近いものを選んだ。事前に計算した値は、06章のt-SNE・UMAP・元の64マスのマップのスコア、クラスタリングチームのARI（GMM 30成分 0.836、K-Means）、02章の標準化したマニュアルさんのマップ（27.0%）、05章の元の64マスでの代表による名前付け（79.2%）だけであり、UMAP（97.6%）を除くすべてをA章のColabコードが同じ値で再現する。UMAPは5-15で測り直す。01章の散布図の点は、重なった点が見えるように±0.35だけ揺らして描き、計算は元の値で行った。03章の「AIが出したコード」はよくある間違いを集めてわざと作った例であり、特定のAIサービスの実際の回答ではない。
      • 応募書類・1枚目。各回00章の9マスの応募書類は、このシリーズのために新しく描いた。ロジスティック回帰の回は、広く使われている9マスの要約インフォグラフィックの構成(二値分類 → 線形スコア → シグモイド関数 → 確率 → 境界 → 閾値 → 損失 → 学習 → 多クラス分類)にならい、元の図とロゴは転載していない。
