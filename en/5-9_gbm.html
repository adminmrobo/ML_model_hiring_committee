GBM — Taking Over the Previous Tree's Error Notebook

5-7 random forest asked a hundred trees separately and averaged them. Today's candidate builds trees one after another. When the first tree gets it roughly right, the second tree learns only how far it is still off (the residuals). The third tree learns the error that remains after adding up to the second. It is a relay that passes an error notebook to the next person.

GBM (Gradient Boosting Machine, gradient boosting) chains together hundreds of shallow trees about 3 levels deep. It trusts each tree's answer only by the learning rate (usually 0.1) when adding it. It does strength (regression) and 35 MPa pass/fail (classification) the same way. Even for classification, the trees inside are regression trees that predict numbers. XGBoost, LightGBM and CatBoost are the same family, implementing this principle faster and more robustly.

2. Residual Residual = What's Still Wrong

The difference between the actual value and the prediction so far. It becomes the target of the next tree.

ri = yi − F(xi)
Equal to the flipped gradient of squared error (panel 6)

3. Shallow tree Weak Learner · Shallow Tree

One tree is a weak employee with just a few questions. Each leaf stores the mean residual of its cell.

This interview's trees: depth 3 = at most 3 questions, at most 8 leaves
One tree alone gets R² 0.12. Weak on its own

4. Additive update Additive Model

It starts with a single mean. Each tree's answer is shrunk by the learning rate and added in turn.

FM(x) = F0 + η Σm=1..M hm(x)
→ 04 Probation

5. Learning rate Learning Rate · Shrinkage

It does not fully trust one tree's answer but takes in only a little (η). The smaller it is, the more trees are needed.

Fm = Fm−1 + η · hm
Choose learning rate × number of trees as a pair
→ 04 Probation

6. What the name means: gradient Gradient in Function Space

The residual points opposite the gradient of the loss function. That is why it is "gradient" boosting.

−∂L/∂F = y − F = residual
The trees correct the predicted values themselves by gradient descent
→ 04 Probation

Even for the 35 MPa pass problem, the trees add numbers (log-odds). The sigmoid turns them into a probability.

p = σ(F) ,   residual = y − p
F₀ = log(pass share ÷ fail share)

Training error keeps falling, but validation error stalls at some point. Stop around there.

The validation fraction is taken from the training data, not the exam paper

Self-introduction — An Employee Who Takes Over the Error Notebook

Try it · predicting strength of 324 28-day mixes (training) from one feature (water–binder ratio) · depth-2 trees

One tree at a time, only what's wrong

The first prediction is a single number: the mean of the training strengths. It answers every mix with the same value, so R² is 0. The first tree learns to predict "how far each mix is from the mean" (the residual). Shrink its answer by the learning rate and add it, and the prediction gets a little better and the residuals shrink a little. The second tree learns the reduced residuals. This repeats hundreds of times. Each tree is a weak learner with only two or three questions, but filling in different mistakes one after another makes them strong. This way of chaining weak ones into something strong is called boosting.

F₀ = mean → r = y − F → h = tree(r) → F ← F + η·h → (repeat)

How is it different from random forest?

Both are ensembles that use hundreds of trees. 5-7 random forest grows deep trees side by side. It re-draws the data for each tree to make them different, and averages their answers to reduce wobble (variance). GBM grows shallow trees in one line. Each next tree learns the error left by the previous ones, and their answers are added to reduce skew (bias). So random forest can grow its trees all at once, but GBM must wait for the previous tree to finish before starting the next.

Random forest: mean(deep trees)  ·  GBM: mean + η·Σ(shallow trees)

How GBM reads the task sheet · trees have no units trap

5-1 KNN measures distance, so adding kg and days as they were made its neighbors meaningless. Trees do not measure distance. They look only at the order of values within one feature, as in "is cement 350 kg or less?" Standardization does not change the order (after subtracting and dividing, large values are still large), so the splits a tree picks stay the same and so do the predictions. Check it yourself with the button on the right.

Pressing the button trains GBM twice on the 772 training mixes: once in the original units (kg, days) and once on standardized values.

What trees read well, and what they cannot

Trees work with thresholds. Because they ask things like "is age 14 days or less?", they can follow along by chaining questions even when ages come in scattered values like 1 · 3 · 7 · 28 days, or when the water–binder ratio and age interact to change strength (interactions such as "water matters only at 28 days or more"). But a tree's answer is a staircase. Outside the range in the training data (water–binder ratio 0.2, age 1,000 days), it answers with the value of the last step. Like 5-1 KNN, it cannot extrapolate.

Swapping the data — to use your own factory's data

  • All you need is a table (CSV, etc.) with one mix (or lot) per row and one column to predict. In the Colab code (Section A), change only the data loading, FEATURES and PASS_MPA in cell 1.
  • Standardization is not needed. But if you put it in the same pipeline as other candidates, doing it does no harm.
  • If there are missing values, HistGradientBoosting takes them as is. For GradientBoosting it depends on the version, so check the docs or fill them in beforehand.
  • For text features (plant, raw-material grade), use one-hot encoding, categorical_features in HistGradientBoosting, or CatBoost's categorical handling.
  • If rows exceed tens of thousands, switch to HistGradientBoosting (or LightGBM / XGBoost) (Section 06).

    ④ Version notes — even the same GBM has changed names
    
    
    The loss names of scikit-learn's GBM have changed. For regression, loss="ls" became "squared_error" (deprecated in 1.0, removed in 1.2); for classification, loss="deviance" became "log_loss" (deprecated in 1.1, removed in 1.3). Using an old name now raises InvalidParameterError. criterion="mse" went the same way. HistGradientBoosting used to require importing from sklearn.experimental import enable_hist_gradient_boosting first, but since 1.0 that is not needed.
    
    
    XGBoost, LightGBM and CatBoost offer fit/predict similar to scikit-learn, but their parameter names and defaults differ. The learning rate may be learning_rate or eta, tree size may be set by number of leaves (num_leaves) instead of depth (max_depth), and where early stopping is set has moved between versions. Check the parameters AI gives you against the official docs for the version you installed. That is why the Section A code on this page uses only scikit-learn.

    Probation · Learning rate × number of trees
    
    
    Probation — How Many Trees, and How Little at a Time
    
    
    Additive updates with 8 features → training residuals thin out → choose the learning rate and number of trees with a validation fraction → the exam paper stays sealed
    
  
    
  
    GBM's probation is the very process of adding trees one at a time. There are two things to choose: how much to trust each tree (learning rate η) and how many trees to stop at (number of trees). They go together: halve η and you need roughly twice as many trees for a similar score. And both are chosen within the training data.
    
  
    
    Animation ① · the error notebook gets thinner — distribution of residuals on the 772 training mixes (8 features, η = 0.1, depth 3)
    
    
    
    
      
      
    
    
    
    
  
    
  
    
    Animation ② · learning rate × number of trees — set aside one in every five rows of the training data (155 mixes) as a validation fraction, and train on 617 up to 600 trees
    
    
    
    
    
    When you reach this section, it trains 600 trees at each of four learning rates and draws the curves (1–2 s in this browser).
    
  
    
  
    
    
    
      
    Why you should not trust training R²
    
      
    As trees are added, the training residuals only shrink. Trees always learn "the remaining error," so if you go all the way, they memorize even each specimen's fluke (specimens of the same mix with different strengths). So training R² climbs toward 1, while the score on unseen mixes stalls or drops at some point. The η = 1.0 curve shows this: trusting one tree's answer completely, it rises fast and bends early.
    
    
    
    
    
      
    Early stopping — the validation fraction gives the stop signal
    
      
    Stop when validation R² no longer improves. This is early stopping. In scikit-learn you turn it on with n_iter_no_change=10, validation_fraction=0.1. It sets aside 10% of the training data and stops if there is no improvement for 10 trees (Section A cell 7: it stops at 257 trees). In this interview, a person decided by looking at the chart. In the stretch where the validation curve is flat, the score is similar however many trees you pick, so the round number 300 trees (η = 0.1, depth 3) is the working condition. The exam paper is still sealed.

    GBAPP-09 → EMP-0009GBM (gradient boosting)Supervised Division › Dual-role Team · Ensemble
    
      
    In one line: an employee who fills in the remaining error to the end. The family that most often comes first on table data. But it has many working conditions, works in one line so training is hard to split up, and if it works too long it memorizes even the flukes.
    
    
    
    
    
      
    
        
    Strengths
    
        
      
          
    • High scores on table data. Its regression R² of 0.949 in this interview is the highest of all candidates so far (Section 06 interim tally).
      • 
          
    • No standardization needed. It works with thresholds, so different units are fine (Section 02).
      • 
          
    • Finds interactions and curved relationships on its own. It follows the intertwined effect of age and water–binder ratio by chaining questions.
      • 
          
    • Regression, classification and ranking in one framework. Just change the loss function. Even classification has regression trees inside.
      • 
        
    
      
    
      
    
        
    Weaknesses
    
        
      
          
    • Many working conditions. Learning rate, number of trees, depth and subsample must be chosen together. It does well even with defaults, but the best scores come from tuning.
      • 
          
    • Learns in sequence. The next tree can only be grown after the previous one finishes, so training is hard to split up. That is why fast implementations (Hist, LightGBM, XGBoost) appeared.
      • 
          
    • Left too long, it memorizes. Training accuracy 99.9%, test 93.4%. It needs early stopping and a small learning rate.
      • 
          
    • Hard to explain. The sum of 300 trees cannot say "because of this clause." Feature importance is only "how often and how heavily it was used," not cause.
      • 
        
    
      
    
    
    
  
    
  
    
    Working conditions · commonly tuned hyperparameters (scikit-learn GradientBoostingRegressor / GradientBoostingClassifier)
    
    
      
    ArgumentDefaultMeaning and usage
    
      
        
    n_estimators100Number of trees to add (for classification with three or more classes, as many per stage as there are classes). 300 in this interview. Even the default 100 passes, with regression R² 0.927 and classification 91.9%.
    
        
    learning_rate0.1η, how much each tree's answer is trusted. Making it small and adding trees usually improves the score but lengthens training. Choose it together with the number of trees (Section 04).
    
        
    max_depth3Number of questions in one tree. Shallow trees (2–5) are the default. Grown fully (None), the first tree memorizes the training data and the residuals for the next trees to learn vanish (Section A cell 8: test R² 0.890).
    
        
    subsample1.0Set below 1 (e.g. 0.8) and each tree uses only a random part of the training data (stochastic gradient boosting). Reduces overfitting and speeds things up.
    
        
    min_samples_leaf1Minimum number of mixes in a leaf. Raising it removes leaves fitted to a single fluky specimen.
    
        
    n_iter_no_change, validation_fractionNone, 0.1Early stopping. Sets aside a validation fraction from the training data and stops if there is no improvement for a set number of trees. The number of trees at stop is n_estimators_.
    
        
    loss"squared_error" / "log_loss"What to minimize. For regression with many outliers, "huber" or "absolute_error"; for interval prediction, "quantile". The old names "ls" and "deviance" are now errors (Section 03).

    Good fit · poor fit
    
    
      
    Good fitRegression and classification on table data with tens to hundreds of features (quality prediction, demand forecasting, defect detection, credit scoring); jobs that need top scores and have time to tune working conditions; a strong baseline in competitions and practice
    
      
    Poor fitData with large raw inputs such as images, sound or long text (deep learning fits); jobs that must predict outside the training range (designing stronger mixes); jobs that must explain the basis of a decision as clauses (Mr. Manual or a shallow decision tree is better); jobs with very little data
    
      
    NoteOn table data, trying "the GBM family first" is a good habit. But put that score side by side with Mr. Manual (human knowledge) and simple candidates (linear models). If the score difference is small, you may choose the one that is easier to explain.

      • Data and calculations. The practical exam is the UCI concrete compressive strength data, 1,030 mixes, and the exam paper is the 258 mixes split with test_size=0.25, stratify=3 strength grades, random_state=42. Sections 01, 02, 04, 05, the interview result, and the 5-9 row of the Section 06 interim tally are computed by this page growing trees directly in the browser (the same rules as scikit-learn GradientBoosting: starting value, friedman_mse splits, leaf values, learning rate; when several splits tie on score, the order of choice may differ). The browser's copy of the data has strengths rounded to two decimal places, so regression R² differs slightly from Colab (Section A) in the third decimal place (300 trees: browser 0.950, Colab 0.949). The validation fraction in Section 04 takes one in every five rows with the training mixes in row-number order, the same as Section A cell 6. The only precomputed values are the HistGradientBoosting scores in Section 06, the 5-1 to 5-8 rows of the interim tally, and the random forest feature importances in Section 05, all computed with Python (scikit-learn 1.9.1, random_state=0); Section A cells 11 and 12 give the same values. XGBoost, LightGBM and CatBoost were not run in this build. The 'AI-generated code' in Section 03 is an example made on purpose from common mistakes, not a real answer from any particular AI service.
      • Application, page 1. The 9-panel application in section 00 of each episode was newly drawn for this series. The logistic regression episode follows the layout of a widely used 9-panel summary infographic (binary classification → linear score → sigmoid → probability → boundary → threshold → loss → learning → multiclass classification); the original images and logos were not copied.
      • Images. The character images are reused from the "AI Algorithm Family Org Chart". The interview room scenes, ID badges and charts are drawn directly by this page in code.
      • The "Hiring Committee" concept. It is a metaphor that compares models to candidates and training and evaluation to an interview. It does not represent a real hiring process or any specific company. Not being hired only means "not a fit for this job"; it does not rank the models.
      • Characters. Money-Robo is the mascot of a service run by the author. The Doctor, the Assistant, the fruit fly researcher, Mr. Manual and the candidates do not represent real people. The money and budget talk in the dialogue is a verbal habit standing for computing cost.
      • Data. The practical exam of the Supervised Division is the Concrete Compressive Strength dataset from the UCI Machine Learning Repository (Yeh, 1998, 1,030 cases, CC BY 4.0). The exam-paper split is the same in every episode: test_size=0.25, stratify=three strength grades, random_state=42 (772 training · 258 test). The strength grades (25 · 45 MPa) and the pass criterion (35 MPa) are thresholds this series set for teaching; they do not replace any design standard.
      • Language. This series is written in Korean. Translations (English · 中文 · 日本語 · Oʻzbekcha · Русский) are added under the same file names after the Korean content is final. Comments and output in the Colab code are left in the original Korean.
