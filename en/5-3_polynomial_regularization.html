Polynomial regression and regularization — draw the curve, put on the reins

Concrete strength rises fast at first with age, then slowly. A single straight line cannot follow this bend. Today's candidate expands the features by raising them to powers and multiplying them together, and then does linear regression on top. The features grew, but the model is still "multiply by weights and add." That is why it is called polynomial regression.

When features swell from 8 to 164, memorizing the training mixes gets easy. So the candidate also wears reins called regularization. It penalizes weights as they grow, so the curve cannot bend however it likes. Depending on how the penalty works, there are three siblings: Ridge, which shrinks evenly; Lasso, which erases to 0; and Elastic Net, which mixes the two.

2. Polynomial features Polynomial Features

Expand feature x into x² and x³. The model is still linear regression, multiplying by weights and adding.

ŷ = w1x + w2x2 + w3x3 + b

3. Feature explosion Feature Explosion

With several features, terms that multiply features together (x₁x₂) are added on top of the powers. Raise the degree and they swell quickly.

features = C(8 + d, d) − 1
d = degree, 8 = original features, −1 = constant column
→ 02 Practical exam

4. Least squares Least Squares

Find the weights that make the sum of squared residuals (actual − predicted) smallest. The same method as 5-2 linear regression.

minimize  Σ (yi − ŷi)2
→ 04 Probation

5. Overfitting Overfitting

Raise the degree and the training score keeps rising, but the score on never-seen data collapses at some point.

→ 05 Performance review

6. Ridge (L2) Ridge Regression

Penalizes the sum of squared weights. Shrinks all weights evenly toward 0 (they don't become 0).

Σ(y − ŷ)2 + α Σ wj2
→ 04 Probation

7. Lasso (L1) Lasso Regression

Penalizes the sum of absolute weights. Erases low-value weights to exactly 0 (a feature-selection effect).

12nΣ(y − ŷ)2 + α Σ |wj|
→ 04 Probation

8. Elastic Net Elastic Net

Mixes L1 and L2 in ratio ρ (l1_ratio). It both erases and keeps similar features together.

… + α [ ρ Σ|w| + 1 − ρ2 Σw2 ]
→ 05 Performance review

9. Choosing α Choosing α (Cross-Validation)

Small α overfits; large α underfits. Choose it by cross-validation inside the training data, not with the exam paper.

The larger α, the stronger the regularization. C in logistic regression · SVM runs the opposite way (C ≈ 1/α).
→ 05 Performance review

Self-introduction · Concept

Self-introduction — draw curves with more features, and hold them with reins

Feature x → x, x², x³, … → linear regression → press the weights with regularization α

λ
Candidate · Polynomial regression and regularizationI give more ingredients to linear regression, which only draws straight lines. Attach x² and x³ next to x, and doing the same "multiply and add" makes a curve. But with too many ingredients, it twists itself to follow every single point. That is when α pulls the reins.
Try it · 28-day strength from the water–binder ratio alone (a toy problem deliberately cut down to 12 training mixes)

Polynomial regression is "linear" regression too

It draws curves, so why is it linear? All the model does is still multiply each feature by a weight and add. What changed is the feature side: it just puts in [x, x², x³] instead of x. Since it is linear in the weights, it uses 5-2 linear regression's least squares as is. With several features, interaction terms that multiply features together, like x₁·x₂, are attached too. These terms handle relationships like "age has a bigger effect when there is more cement."

ŷ = w₁x + w₂x² + w₃x³ + b  ← linear in w

Regularization is a penalty

Least squares looks only at the training error. With many features, very large weights cancel each other out to make a curve that passes through every single point. Regularization adds "a penalty for large weights" to the loss. α is the strength of that penalty. At α = 0 there is no regularization; with a large α, the weights are pressed toward 0 and the curve straightens. Too large and it becomes a flat line, worse than even a straight line (underfitting).

Loss = sum of error² + α × (size of weights)

What to look for in the chart above

Raise the degree from 1 → 3 and the curve follows the bend in the points. Go up to 10 with α at 0, and the curve swings up and down between the black dots (training) and misses the gray dots (test) badly. Training R² rises while test R² drops below zero. This is overfitting. Now keep the degree at 10 and raise only α. The curve calms down and test R² comes back. This whole interview scales this one chart up to the full concrete data (8 features, 164).

Why standardize twice?

First, standardize the 8 original features (mean 0, std. dev. 1). If you raise them to powers as they are, 1,000 kg of coarse aggregate cubed becomes a billion while superplasticizer stays at a few dozen, and the difference in number sizes gets out of hand. After making polynomial features, standardize once more. Regularization penalizes "the size of weights," so if columns have different units, the penalty becomes unfair. Both times, the mean and standard deviation come from the training data only.

Original features → standardize → polynomial features (164) → standardize → Ridge · Lasso · Elastic Net

Swapping the data — to use your own factory's data

  • All you need is a table (CSV etc.) with one mix (or lot) per row and one column of the number you want to predict.
  • Change only two places in cell 1 of the Colab code (Section A): the data loading and FEATURES. Replace Mr. Manual's empirical formula (cell 3) with your job's empirical formula or existing calculation sheet.
  • With just over 20 features, degree-3 polynomial features number 1,770. Once features outnumber the mixes, it can't be solved without regularization. Start from degree 2.
  • Turn text features (plant, raw-material grade) into numeric columns with one-hot encoding. Raising a one-hot column to a power gives the same value, so only interaction terms are meaningful (interaction_only).
  • For mixes outside the strength range (very low water–binder ratio, etc.), polynomial curves easily miss badly. Record the data range and don't use the model outside it.

    Preparing calculation…
    
    
    The playback starts at α = 100 and goes down to 0.001. At each α it solves again starting from the previous α's answer (warm start). "One sweep of coordinate descent" sets all weights to 0 for Lasso · Elastic Net and updates them one sweep at a time (all 164, one by one) at the current α. Ridge is solved in one go, so one sweep is the end. The test R² in the line chart below is shown only for explanation; using it to choose α is cheating (cross-validation in Section 05).
    
  
    
  
    
    
    
      
    Ridge solves in one go — the closed-form solution
    
      
    The loss of the sum of squared errors plus α·Σw² is a smooth bowl, so its bottom can be found directly with one formula. It is 5-2 linear regression's normal equation with α added along the diagonal. Thanks to this α, the answer stays stable even when features carry almost the same information (a large condition number) and the solution would otherwise wobble. That is why Ridge first appeared in 1970.
    
      
    w = (XᵀX + αI)⁻¹ Xᵀy
    
    
    
    
    
      
    Lasso updates one at a time — coordinate descent
    
      
    The absolute value |w| is pointed at 0, so it can't be solved with one formula. So the weights are updated one at a time in turn. If only the j-th weight moves, the answer is "the share left after the other weights have explained what they can (ρⱼ)" shaved down by α. If the remaining share is smaller than α, it becomes exactly 0. This shaving is called soft thresholding. Go around all 164 once, and repeat until nothing changes.
    
      
    wⱼ ← S(ρⱼ, α) = sign(ρⱼ) · max(|ρⱼ| − α, 0)
    
    
    
  
    
  
    
    
    Budget officer · AbaBotI like Lasso. At α = 0.1 it erases 98 of 164 to 0, so the numbers to memorize drop to 66 (+ intercept). Ridge doesn't erase a single one; it just shaves a little off all of them.

    HR card — where to deploy it and how to manage it
    
    
    Strengths and weaknesses, good and poor fits, working conditions (hyperparameters)
    
  
    
  
    
    
    
      
    λAPP-03 → EMP-0003Polynomial regression and regularizationSupervised Division › Regression Team
    
      
    In one line: linear regression that draws curves with more ingredients and keeps them in check with reins. Hold its two knobs, degree and α, well, and it beats the empirical formula. Let go of the knobs and it runs away.
    
    
    
    
    
      
    
        
    Strengths
    
        
      
          
    • It captures curves and interactions. Even without a person making log(age) or the water–binder ratio, degree-3 terms imitate the bend (R² 0.567 → 0.849).
      • 
          
    • It is still linear regression. Training is fast (Ridge is one formula), and the same input always gives the same answer.
      • 
          
    • Regularization adds a safety device. Ridge stabilizes an unstable solution, and Lasso erases low-value terms to make the model lighter.
      • 
          
    • It becomes an ingredient for other candidates. Polynomial features + logistic regression, and polynomial-kernel SVM (5-8), use the same idea.
      • 
        
    
      
    
      
    
        
    Weaknesses
    
        
      
          
    • Features explode. Degree 4 of 8 features gives 494; degree 3 of 20 gives 1,770. Once they outnumber the mixes, it can't be solved without regularization.
      • 
          
    • It goes wild outside the data range. Powers jump sharply when you step even a little outside the range. The degree-4 runaway is exactly this.
      • 
          
    • Explanation gets harder. Weights of terms like "age²·cement" are hard for people to read. Even when Lasso erases terms, the remaining ones are not necessarily causes.
      • 
          
    • It has two knobs. Degree and α must be chosen together, and both need cross-validation.
      • 
        
    
      
    
    
    
  
    
  
    
    Terms Lasso kept · nonzero weights among 164 degree-3 polynomial features (standardized features, top 12 by size)
    
    
    
    
    
    
  
    
  
    
    Working conditions · hyperparameters often adjusted (scikit-learn)
    
    
      
    ArgumentDefaultMeaning and usage
    
      
        
    PolynomialFeatures(degree)2The degree. Start from 2 and raise it by cross-validation. On this data degree 3 was best, and degree 4 ran away without regularization (Section 05).
    
        
    include_biasTrueWhether to make a constant column (1). The regression model that follows has its own intercept, so set it to False. With True, degree-3 features count as 165.
    
        
    interaction_onlyFalseWith True, it makes only cross-product terms (x₁x₂), without x²·x³. Use it for columns that stay the same when squared, such as one-hot features.
    
        
    alpha (Ridge·Lasso·ElasticNet)1.0Regularization strength. Larger is stronger. It runs opposite to C in logistic regression · SVM (C ≈ 1/α). RidgeCV·LassoCV·ElasticNetCV choose it by cross-validation.
    
        
    l1_ratio (ElasticNet)0.5The L1 ratio ρ. 1 is Lasso; close to 0 is Ridge. With many similar features, around 0.5 keeps them together.
    
        
    max_iter, tol (Lasso·ElasticNet)1000, 1e-4The iteration limit and stopping criterion of coordinate descent. If a ConvergenceWarning appears at small α, increase max_iter.
    
          
    
    
  
    
  
    
    
    
      α and C — the same knob, opposite scales
      
      
    Remember C ≈ 1/α. The red side means "press the weights hard." This direction mistake appears in Section 03's spot-the-errors of 5-4 logistic regression.
    
    
    
    
    
      Good fit · poor fit
      
    
        
    Good fitCapturing bending relationships and interactions in tabular data with a few to a few dozen features (mix → strength, temperature · pressure → yield), refining empirical formulas with data, predictions that need to be fast and always give the same answer
    
        
    Poor fitData with hundreds of features or more (polynomial features explode), predicting outside the training range (extrapolation), step-like relationships (→ decision tree 5-6), raw data such as images and sound
    
        
    NoteLasso is "regularization." It selects features as a result of erasing low-value terms, but it does not create meaningful new features like the water–binder ratio (feature engineering is a person's job). In 5-2, adding two human-made features (water–binder ratio, log age) to the 8 features gave R² 0.842 (11 numbers to memorize), almost the same as 0.849 from 164 degree-3 features.

      Notes on the data, images and concept of this page
      
  
      • Data and calculations. The practical exam is the UCI Concrete Compressive Strength data, 1,030 mixes; the exam paper is the 258 mixes split with test_size=0.25, stratify=3 strength grades, random_state=42. The Regression Team hiring bar is the R² of 0.735 that Mr. Manual's field formula (Abrams' law f28 = 96.5 / 7^(water–binder ratio) MPa multiplied by the ACI 209R age correction t / (4 + 0.85t), widened to the water–binder ratio instead of the water–cement ratio) scored on the exam paper. The constants are textbook values used as is and do not replace any plant's design standard. The numbers in Sections 01·04·05·06 and the interview result are calculated directly in the browser by this page. Polynomial features are made in the same order as scikit-learn PolynomialFeatures(include_bias=False) (164 for degree 3, or 165 counting the constant column); Ridge uses the closed-form solution (Cholesky decomposition), and Lasso · Elastic Net solve the same objective function as scikit-learn by coordinate descent. Up to degree 3 the browser calculation is fast enough, so no demo model with fewer degrees or features was used. Only the curve chart in Section 01 is a toy problem cut down for explanation to 12 of the 28-day mixes and one feature (water–binder ratio). Degree-4 polynomial regression (494 features, no regularization) has a very unstable solution (condition number about 10⁶–10⁷), so its test R² varies greatly with the calculation method: about −23.6 in the browser (normal equation), −6.18 in Colab (scikit-learn LinearRegression), and −11.3 with one more standardization after the polynomial step. The numbers differ, but the conclusion, 'training 0.98, test strongly negative,' is the same. Cross-validation deals the training mixes in turn into five folds (the same as PredefinedSplit in Colab). The 'AI-written code' in Section 03 is a deliberately constructed example collecting common mistakes, not an actual answer from any particular AI service.
      • Application, page 1. The 9-panel application in section 00 of each episode was newly drawn for this series. The logistic regression episode follows the layout of a widely used 9-panel summary infographic (binary classification → linear score → sigmoid → probability → boundary → threshold → loss → learning → multiclass classification); the original images and logos were not copied.
      • Images. The character images are reused from the "AI Algorithm Family Org Chart". The interview room scenes, ID badges and charts are drawn directly by this page in code.
      • The "Hiring Committee" concept. It is a metaphor that compares models to candidates and training and evaluation to an interview. It does not represent a real hiring process or any specific company. Not being hired only means "not a fit for this job"; it does not rank the models.
      • Characters. The Doctor, the Assistant, the fruit fly researcher, AbaBot, Mr. Manual and the candidates do not represent real people. The money and budget talk in the dialogue is a verbal habit standing for computing cost.
      • Data. The practical exam of the Supervised Division is the Concrete Compressive Strength dataset from the UCI Machine Learning Repository (Yeh, 1998, 1,030 cases, CC BY 4.0). The exam-paper split is the same in every episode: test_size=0.25, stratify=three strength grades, random_state=42 (772 training · 258 test). The strength grades (25 · 45 MPa) and the pass criterion (35 MPa) are thresholds this series set for teaching; they do not replace any design standard.
      • Language. This series is written in Korean. Translations (English · 中文 · 日本語 · Oʻzbekcha · Русский) are added under the same file names after the Korean content is final. Comments and output in the Colab code are left in the original Korean.
