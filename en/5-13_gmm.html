GMM — sharing through overlapping bells

The 1,797 handwritten digits in the factory logbooks have no name tags. Today's candidate assumes the digits came from a mix of ten bells. Each bell has its own place (mean), shape (covariance) and share (mixture weight). A digit is not put firmly into one bell; it is shared by probability, like "bell 3 with probability 0.7, bell 8 with probability 0.3".

GMM (Gaussian Mixture Model) is the probabilistic version of 5-10 K-Means. Unlike K-Means, which has only centroids, it also learns each bell's tilt and spread, and it can even draw new digits from those bells. In exchange it has many numbers to memorize, so it works only after first reducing the 64 pixels to 30 axes.

The probabilistic version of K-Means

5-10 K-Means repeated two steps: put each point firmly into the nearest centroid, then move the centroid to the cluster mean. GMM also has two steps. The E step uses the current bells to split each digit into "probability of bell 1, probability of bell 2, …". The M step uses those probabilities as shares to re-measure each bell's weight, mean and covariance. Each round, "how plausible it is that these bells produced these digits" (the likelihood) rises, and it never falls. This method is called the EM algorithm.

E: γik ∝ πk·N(xi | μk, Σk) → M: πk = Σiγik/n, μk = weighted mean, Σk = weighted covariance

Bell = mean + covariance + weight

A K-Means cluster is just one centroid plus the rule "whichever is closer", so in effect it assumes clusters are always round and the same size. A GMM bell is an ellipse. The covariance sets the ellipse's size and tilt, so it handles long, tilted clusters (a 7 with a slanted stroke) and small, round ones (a round 0) together. The weight is that bell's share of the whole. So where bells overlap, the bell with the larger share takes a bit more.

In GMM, make the covariance a circle and shrink the spread to 0 → K-Means

One bell's covariance is 64 × 65 ÷ 2 = 2,080 numbers. With ten bells, plus the means, that is over 20,000, but there are only 1,797 images. What's more, the always-0 edge pixels have zero spread, so the covariance cannot be inverted (it is forced by adding a tiny value). So it works with only the 30 "directions of greatest spread" kept by PCA. The covariance on 30 axes is 465 numbers. This reducing is the specialty of the next candidate, 5-14 PCA.

What GMM reads well, and what it doesn't

Bells fit data of continuous numbers spread out like ellipses. Handwriting brightness is a number from 0 to 16, and images of the same digit spread around an average digit, so it fits fairly well. It reads poorly: clusters bent like a banana (it covers them with several ellipses), cases with too many dimensions for the data (the ledger problem above), and tables whose columns are not all in the same unit (then use it after standardization). When every pixel has the same unit, as in handwriting, do not standardize. The nearly always-0 edge pixels get blown up, which actually hurts (Section 03).

Swapping the data — to use your own factory's data

  • All you need is one sample per row (a photo, a sensor record, a lot) and numeric features as columns. Change only X in cell 1 of the Colab code (Section A). You don't need answers. If you have them, use them only for grading.
  • A photo becomes a number matrix if you flatten its pixels into one row (Image classification episode 4-2). Match the sizes, and if there are many pixels, reduce them first with PCA.
  • If features with different units (temperature, pressure, time) are mixed, standardize, then reduce with PCA.
  • If you don't know the number of clusters, pick candidates with BIC (Section 04), then have a person look at a few representatives per cluster and merge or split.
  • Text features or blanks can't go straight into GMM. Convert them to numbers and fill them in.

    ④ Version notes — GMM has been renamed before
    
    
    scikit-learn's old sklearn.mixture.GMM class was replaced by GaussianMixture in 0.18 and removed in 0.20. The Dirichlet process versions DPGMM and VBGMM were also merged into one, BayesianGaussianMixture. If an AI trained on old blog code gives you from sklearn.mixture import GMM, you now get an ImportError. Argument names changed too (n_iter → max_iter; the values of covariance_type stayed the same).
    
    
    What can still change is the defaults. The default of init_params is "kmeans", and you can also choose "k-means++" and "random_from_data" (from 1.1). Changing the start changes the result (Section 04), so check the AI's arguments against the official docs for the version you installed, and when you record results, write down the version and random_state too.

    What BIC chose, and what the committee decided
    
      
    BIC chose full covariance. full is smallest at every k. For the number of bells, k = 8 (299,782) is smallest, with 9 (300,814) and 10 (300,818) right behind. "There are ten kinds of digits" is information inside the sealed answer envelope, so you can't know it without the answers. But the person in charge of this job knows the digits are 0–9. The committee used this domain knowledge to set k = 10 as a working condition. What would have happened with BIC's k = 8 is checked under "Change conditions and look again" in the interview result.
    
    
    
    
    
      
    Likelihood always rises, so a penalty is needed
    
      
    The more bells you add or the freer the covariance, the more the likelihood only rises. At the extreme, one bell per digit fits perfectly. But that is memorization. BIC charges a penalty of ln(1,797) ≈ 7.5 for each number to memorize (parameter). That is why the curve becomes U-shaped. AIC's penalty is lighter, at 2. Both BIC and AIC are measured without the answers. They can only be compared on the same data with the same dimensions (don't compare a 30-axis BIC with a 64-pixel BIC).
    
    
    
  
    
  
    
    
    Money-Robo (budget officer)Ledger's done. One full bell on 30 axes: mean 30 + covariance 465 = 495; ten of them plus 9 weights is 4,959. On the raw 64 pixels it would've been 21,449. So we cut it to a quarter. K-Means only needed 640 for its centroids, so this is still a pricey hire. But it also tells you "how plausible" each digit is, so it earns its pay.

    HR card — where to deploy it and how to manage it
    
    
    Strengths and weaknesses, working conditions (hyperparameters), drawing new digits, the next candidate
    
  
    
  
    
    
    
      
    NAPP-13 → EMP-0013GMM (Gaussian mixture model)Unsupervised Division › Clustering Team
    
      
    In one line: an employee who writes ambiguity down as numbers. It handles tilted elliptical clusters, tells you "how plausible" each digit is, and even draws new digits. In exchange, its ledger is thick, it depends on the start, and in high dimensions it is overconfident in its probabilities.
    
    
    
    
    
      
    
        
    Strengths
    
        
      
          
    • Top ARI on the Clustering Team. This interview's 0.836 beats K-Means 0.666 and hierarchical ward 0.794 (Section 05).
      • 
          
    • Tilted elliptical clusters. Clusters can differ in size, tilt and share. It covers the weakness of K-Means, which only knows round clusters.
      • 
          
    • It gives density. Each digit gets a likelihood, which finds "digits that fit no cluster" (outliers). Rechecking only these raises task accuracy quickly.
      • 
          
    • Generative model. It can sample new digits from the bells it learned (below).
      • 
        
    
      
    
      
    
        
    Weaknesses
    
        
      
          
    • Thick ledger. Full covariance grows with the square of the dimensions. On the raw 64 pixels there are over 20,000 parameters and ARI drops to 0.611. You must reduce first.
      • 
          
    • Depends on the start. ARI 0.630–0.836 depending on random_state. You need several starts with n_init.
      • 
          
    • Overconfident probabilities. On 30 axes almost every digit gets 0.99 or more, yet about 8% are wrong. Don't read probabilities as accuracy.
      • 
          
    • You must set the number of clusters. BIC chose 8. Without domain knowledge, a person has to inspect the clusters.
      • 
        
    
      
    
    
    
  
    
  
    
    Working conditions · commonly tuned hyperparameters (scikit-learn GaussianMixture)
    
    
      
    ArgumentDefaultMeaning and usage
    
      
        
    n_components1The number of bells to mix, k. This interview: 10 (domain knowledge). If unknown, pick candidates with BIC (Section 04; BIC chose 8).
    
        
    covariance_type"full"How freely the bells are shaped. full (tilted ellipses) · tied (all share one ellipse) · diag (axis-aligned ellipses) · spherical (circles). On this data, full was best both by BIC and by grading.
    
        
    n_init1How many times to run from different starts. Keeps the result with the highest likelihood. This data depends heavily on the start, so 5–10 is recommended (ARI 0.840 with n_init=10).
    
        
    init_params"kmeans"How the starting clusters are made. "k-means++", "random" and "random_from_data" are also available.
    
        
    random_stateNoneThe random seed for the start. Fix it to get the same result. This interview: 0.
    
        
    reg_covar1e-6A small value added to the covariance diagonal. It keeps features that always have the same value from breaking the computation. On the raw 64 pixels, this value strongly shapes the result.
    
        
    max_iter, tol100, 1e-3The cap on EM iterations and the stopping criterion (change in mean log-likelihood). This interview stopped after 16 iterations. Check with converged_.
    
          
    
    
    
    Note: BayesianGaussianMixture is a variant that, given a generous number of bells, shrinks the weights of unneeded bells to near 0 and so decides the number of clusters itself (Dirichlet process prior). It is worth trying alongside BIC for jobs where the number of clusters is unknown.
    
  
    
  
    
    New digits drawn by GMM · sample two per bell and run PCA backwards (browser computation)
    
    
    
    
    
    For each bell (cluster), one 30-axis point is sampled from its mean and covariance (following the tilted ellipse via Cholesky decomposition), then the 30 axes are mapped back to 64 pixels and clipped to 0–16. These digits appear nowhere in the 1,797 images. They are a bit blurry and blotchy because of the 34 discarded axes and the limits of the bell shape. A model that learns the data's distribution and can produce new samples like this is called a generative model.
    
  
    
  
    
    
    Money-Robo (budget officer)Name ten representatives, recheck just the 180 low-likelihood images, and you get 96%? That's nearly ten times less work than labeling all 1,797. Thick ledger or not, if it saves human hands, it's a profitable deal!
    
  
    
  
    
    Good fit · poor fit
    
    
      
    Good fitClustering continuous data whose clusters differ in size and shape (reduced image features, sensor signals), jobs that must mark ambiguous samples with probabilities, outlier detection that finds "the unusual" by density, and jobs that must imitate the data distribution (synthetic samples, classic models in speech processing)
    
      
    Poor fitRaw data with far too many dimensions for the amount of data (reduce first), clusters bent like bananas or rings (5-12 DBSCAN and 5-11 hierarchical single are better), tables with many text features, and jobs that must report probabilities directly as accuracy (it is overconfident in high dimensions)
    
      
    NoteGMM shone not alone but working together with reduction. The next candidate, 5-14 PCA, shows how the 30 axes used today are made, and what you lose if you keep only 2.

The PCA, EM, BIC, ARI, NMI, silhouette, task score and new digits in Sections 01·02·04·05·06 and the interview result are computed by this page directly in the browser (same rules as scikit-learn GaussianMixture: start from K-Means clusters, reg_covar 1e-6, tol 1e-3). For the main model, the covariance type comparison, k = 8, and the raw 64 pixels, the starting clusters are the K-Means (n_init=1) result that scikit-learn uses inside GaussianMixture(random_state=0), precomputed in Python; the browser runs EM from that start and produces the same clusters, BIC (300,818) and iteration count (16) as scikit-learn. Starts B–E in Section 04 ②, the 2-axis picture in Section 01, and the 2-axis probability distribution in Section 05 use this browser's k-means++ starts, so their numbers differ from scikit-learn's other random_state values. The only precomputed values are the starting clusters above, the BIC curves in Section 04 ③ (4 covariance types × k = 2–20, random_state=0), and 5-10 K-Means (0.666) and 5-11 ward (0.794) in the Section 05 Clustering Team comparison; all were computed in Python (scikit-learn 1.9.1), and cells 7·11 of Section A give the same values. The 'ambiguous digits', 'low-likelihood digits' and representative names in Section 05 are analyses done after opening the sealed answer envelope. The 'AI-generated code' in Section 03 is an example deliberately built from common mistakes, not an actual answer from any particular AI service.

      • The "Hiring Committee" concept. It is a metaphor that compares models to candidates and training and evaluation to an interview. It does not represent a real hiring process or any specific company. Not being hired only means "not a fit for this job"; it does not rank the models.

The strength grades (25 · 45 MPa) and the pass criterion (35 MPa) are thresholds this series set for teaching; they do not replace any design standard.
